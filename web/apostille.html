ERC-8004: connect the agent to an identity record

Use a private, detached binding to connect an Apostille agent with a token in an ERC-8004 registry. The signed record travels alongside the artifact bundle; Core 0.1 stays unchanged.

  1. Register the agent in your workspace. If ERC-8004 is enabled, select a configured registry and enter the token ID in the existing workspace panel.
  2. The administrator signs the binding request and the EOA owner signs a wallet consent message. The issuer reads ownership at a finalized block; no blockchain transaction is signed or sent.
  3. Download the private signed snapshot. A recipient verifies it offline using an independently trusted issuer and key pin. The result records issuer_checked; it does not re-query the registry.

This checks the token owner observed by the issuer at one finalized block. It does not prove current ownership, organization identity, capabilities, or payment authority.

ZK budget: check a limit without sharing each amount

For an internal budget review, the source department commits to a list of expenses and signs its public commitment manifest. The receiving department can check that the committed total stays within its chosen limit.

  1. The source creates a private snapshot of 1–16 nonnegative integer amounts and signs the public manifest with its agent key.
  2. The receiver chooses the request: snapshot, limit, audience, nonce and expiry. It independently selects the source key pin and verification key pin.
  3. The source generates a proof locally. The receiver checks it offline with the Go SDK or CLI and records nonce use in its own workflow.
Stays in the source department
Individual amounts, blinding, private snapshot and signing keys.
Visible to the recipient
The result, limit, scope, period, entry count, source key and snapshot hash. These can link records.

The proof covers only the committed list. It does not establish whether the source data is true or complete, current authorization or payment approval. Repeated limit queries can reveal information about the total.

The alpha uses a single-party development setup. An operator who retains its secret setup material could forge proofs; there is no production ceremony or external security audit yet.
